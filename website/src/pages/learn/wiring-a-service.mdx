A service is wired by hand, in one function. There is no container, no scanning and no
annotation to register things with - and nothing is missing because of it. In Python, listing
the parts is a function, the order is the order you read it in, and there is nothing to discover
because you can see it.

## The shape

One function returning one object. Nothing above it knows which database, which handlers or
which jobs; nothing below it does either.

Both are your code - here, the example's: `build()` creates ekbatan's objects, and
`WalletService` is a class the example writes to hold them. ekbatan provides neither.

<ModeTabs>
<div slot="sync">

```python
@dataclass(frozen=True, slots=True)
class WalletService:
    registry: DatabaseRegistry
    wallet_repository: WalletRepository
    executor: ActionExecutor
    locks: KeyedLockProvider
    jobs: JobRegistry

    def start(self) -> None:
        self.jobs.start()

    def close(self) -> None:
        # Order matters: stop taking work before closing what the work runs on.
        self.jobs.stop()
        self.locks.close()
        self.registry.close()
```

</div>
<div slot="async">

```python
@dataclass(frozen=True, slots=True)
class WalletService:
    registry: AsyncDatabaseRegistry      # the requests, awaited
    wallet_repository: WalletRepository
    executor: AsyncActionExecutor
    locks: AsyncKeyedLockProvider
    events_registry: DatabaseRegistry    # sync: fan-out, dispatch and the jobs
    jobs: JobRegistry

    def start(self) -> None:
        self.jobs.start()

    async def aclose(self) -> None:
        # Order matters: stop taking work before closing what the work runs on. Stopping the
        # jobs waits for work in flight, so it runs on a thread, off the event loop.
        await asyncio.to_thread(self.jobs.stop)
        self.events_registry.close()
        self.locks.close()
        await self.registry.aclose()
```

</div>
</ModeTabs>

## Migrate before anything opens a pool

```python
if config.run_migrations:

```

</div>
<div slot="async">

```python
if config.run_migrations:
    migrate(layout, MIGRATIONS)      # sync in both modes, before the first await

registry = AsyncDatabaseRegistry.from_config(layout)
```

</div>

`migrate` applies your plain SQL migration files, using the yoyo migration library from inside
your program: there is no separate tool to install and no config file to find.

It refuses to run if an applied migration has since been edited, renamed or deleted, or if a new
one is older than one already applied, so the files and the database never quietly disagree.
Several replicas starting at once is
safe: each database is locked while it is migrated, one process migrates and the rest wait.

There is no `@EkbatanAction` and nothing scanning your package for one. The framework knows
about exactly what you put in a registry. That is a real trade:

- an action you forget to register fails at `execute` — at runtime, not when the program is
  built;
- against that, you can read this file and know what the program contains.

`namespace` is written on every outbox row: it is how a consumer tells one service's events from
another's. It must be **dot-separated names, shaped like a Python package**, such as
`com.example.wallets`. A hyphen is refused at startup, because the namespace is also used as a
package name when events are streamed as Protobuf, which does not allow one. Write `my_service`,
not `my-service`.

## Three pools, and why

This is the part worth copying into a real deployment.

| pool | sized for | why it is separate |
|---|---|---|
| **requests** | concurrent requests | the ordinary one |
| **jobs** | `workers + 3` | each worker needs one, and so do the scheduler's own three loops: finding due jobs, the heartbeat that marks running jobs alive, and spotting dead ones. Share the request pool and a burst of traffic can starve the heartbeat - and **a job whose heartbeat stops is taken for dead and run again somewhere else** |
| **locks** | maximum leases held at once | a keyed lock holds its connection for the life of the lease. That *is* the lock |

The examples give the jobs pool 8 connections: a job that holds the last free connection would
leave the heartbeat without one. The scheduler warns at startup when the pool is too small for
its workers.

An async service keeps all three - the requests and the locks async, the jobs sync - and adds a
fourth for an async event handler, which runs on a loop of its own. See
[Wiring](/reference/wiring/).

## Under FastAPI

Call `build()` once, in a lifespan - the example's `start()` and `close()` start and stop the
job registry and close the registry and the data sources:

<ModeTabs>
<div slot="sync">

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    # sync work, on a worker thread: the sync API is refused on the event loop's own
    service = await asyncio.to_thread(build, settings)
    await asyncio.to_thread(service.start)
    app.state.service = service
    try:
        yield
    finally:
        await asyncio.to_thread(service.close)
```

</div>
<div slot="async">

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    # building runs the migrations and starting registers the jobs: both sync, so both on a
    # worker thread - the sync API is refused on the event loop's own
    service = await asyncio.to_thread(build, settings)
    await asyncio.to_thread(service.start)
    app.state.service = service
    try:
        yield
    finally:
        await service.aclose()
```

</div>
</ModeTabs>

Three traps, all of which cost real time:

**The dependency alias must be at module level.**

```python
Service = Annotated[WalletService, Depends(service_of)]
```

With `from __future__ import annotations`, FastAPI looks the alias up at module level. One
defined inside `create_app` is not found, so the parameter is taken for a **query parameter**
instead. The symptom is a 422 error on every endpoint, naming a field nobody declared.

**Use `def`, not `async def`, with the sync API.** FastAPI runs a plain `def` endpoint in a
threadpool, so a blocking database call blocks one worker thread. An `async def` endpoint runs on the event loop, where the same call stops **every** request on
that worker until it returns. For `async def` endpoints, build the request path on `ekbatan.aio` instead - the Async samples
on this page, and [Wiring with FastAPI](/reference/wiring-fastapi/).

**An exception handler must `return` a response, not raise one.** A raise from inside a handler
is not caught again and becomes a 500 — the opposite of what they exist for.
