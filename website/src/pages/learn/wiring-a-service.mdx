A service is wired by hand, in one function. There is no container, no scanning and no
annotation to register things with - and nothing is missing because of it. In Python, listing
the parts is a function, the order is the order you read it in, and there is nothing to discover
because you can see it.

## The shape

One function returning one object. Nothing above it knows which database, which handlers or
which jobs; nothing below it does either.

<ModeTabs>
<div slot="sync">

```python
@dataclass(frozen=True, slots=True)
class WalletService:
    registry: DatabaseRegistry
    wallets: WalletRepository
    executor: ActionExecutor
    locks: KeyedLockProvider
    jobs: JobRegistry

    def start(self) -> None:
        self.jobs.start()

    def close(self) -> None:
        # Order matters: stop taking work before closing what the work runs on.
        self.jobs.stop()
        self.locks.close()
        self.registry.close()
```

</div>
<div slot="async">

```python
@dataclass(frozen=True, slots=True)
class WalletService:
    registry: AsyncDatabaseRegistry      # the requests, awaited
    wallets: WalletRepository
    executor: AsyncActionExecutor
    locks: AsyncKeyedLockProvider
    events_registry: DatabaseRegistry    # sync: fan-out, dispatch and the jobs
    jobs: JobRegistry

    def start(self) -> None:
        self.jobs.start()

    async def aclose(self) -> None:
        # Order matters: stop taking work before closing what the work runs on. Stopping the
        # jobs waits for work in flight, so it runs on a thread, off the event loop.
        await asyncio.to_thread(self.jobs.stop)
        self.events_registry.close()
        self.locks.close()
        await self.registry.aclose()
```

</div>
</ModeTabs>

## Migrate before anything opens a pool

<ModeTabs>
<div slot="sync">

```python
if config.run_migrations:
    migrate(layout, MIGRATIONS)

registry = DatabaseRegistry.from_config(layout)
```

</div>
<div slot="async">

```python
if config.run_migrations:
    migrate(layout, MIGRATIONS)      # sync in both modes, before the first await

registry = AsyncDatabaseRegistry.from_config(layout)
```

</div>
</ModeTabs>

`migrate` runs plain SQL files through yoyo as a **library** — there is no config file and no
binary, because a config file that has to be found is a config file that is missing in the one
environment you did not test.

It refuses to run if an applied migration has since been edited, renamed or deleted, or if a new
one is older than one already applied, so the files and the database never quietly disagree.
Several replicas starting at once is
safe: each database is locked while it is migrated, one process migrates and the rest wait.

There is no `@EkbatanAction` and nothing scanning your package for one. The framework knows
about exactly what you put in a registry. That is a real trade:

- an action you forget to register fails at `execute` — at runtime, not when the program is
  built;
- against that, you can read this file and know what the program contains.

`namespace` is stamped on every outbox row and is how a consumer tells one service's events from
another's. It must be **dot-separated identifiers, shaped like a package** — and a hyphen is
refused at startup, because the namespace doubles as a schema package when streaming and
`package my-service;` is a protobuf syntax error. Write `my_service`.

## Three pools, and why

This is the part worth copying into a real deployment.

| pool | sized for | why it is separate |
|---|---|---|
| **requests** | concurrent requests | the ordinary one |
| **jobs** | `workers + 3` | the scheduler heartbeats from a housekeeping thread. Share the request pool and a traffic burst can starve that heartbeat — and **an execution whose heartbeat stops is declared dead and run again somewhere else** |
| **locks** | maximum leases held at once | a keyed lock holds its connection for the life of the lease. That *is* the lock |

The jobs pool default is 8, not 3, for a reason worth repeating: a job body holding the last
connection starves the heartbeat. The scheduler warns at startup when the pool is too small —
and did, while the examples were being written.

An async service keeps all three - the requests and the locks async, the jobs sync - and adds a
fourth for an async event handler, which runs on a loop of its own. See
[Wiring](/reference/wiring/).

## Under FastAPI

Build once, in a lifespan:

<ModeTabs>
<div slot="sync">

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    service = build(settings)
    service.start()
    app.state.service = service
    try:
        yield
    finally:
        service.close()
```

</div>
<div slot="async">

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    service = build(settings)        # sync: building opens no connection
    service.start()
    app.state.service = service
    try:
        yield
    finally:
        await service.aclose()
```

</div>
</ModeTabs>

Three traps, all of which cost real time:

**The dependency alias must be at module level.**

```python
Service = Annotated[WalletService, Depends(service_of)]
```

With `from __future__ import annotations`, FastAPI resolves string annotations against the
*module* namespace. An alias defined inside `create_app` is invisible to that lookup, so the
parameter is read as an unfilled **query parameter** instead. The symptom is a 422 on every
endpoint, naming a field nobody declared.

**Use `def`, not `async def`, with the sync API.** FastAPI runs a plain `def` endpoint in a
threadpool, so a blocking database call blocks one worker thread. An `async def` endpoint runs
on the event loop, where the same call stops **every** request on that worker. Measured: a 0.5s
call from an `async def` handler let a heartbeat tick 5 times where a free loop manages about 55.
For `async def` endpoints, build the request path on `ekbatan.aio` instead - the Async samples
on this page, and [Wiring with FastAPI](/reference/wiring-fastapi/).

**An exception handler must `return` a response, not raise one.** A raise from inside a handler
is not caught again and becomes a 500 — the opposite of what they exist for.
