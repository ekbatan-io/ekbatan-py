## Type signature

```python
@dataclass(frozen=True, kw_only=True)
class Alert(Entity[Id["Alert"], GenericState, AlertBuilder]):
    wallet_id: ShardedId[Wallet]
    recipient: str
    message: str
```

`Entity[ID, S]` takes the id type and, optionally, a state enum. `S` **defaults** —
`Entity[Id[Alert]]` is `Entity[Id[Alert], GenericState]`, and `GenericState` is `ACTIVE` /
`DELETED`, which is usually all an entity needs. A model has no such default, because a model
with no lifecycle of its own is nearly always a model nobody has thought about yet.

```python
class Entity[ID, S: Enum = GenericState, B: EntityBuilder = EntityBuilder](
    Persistable[ID, S, B]
):
    id: ID
    state: S
    version: int    # required, 1 or more

    @property
    def is_model(self) -> bool: ...        # always False on Entity
    @property
    def is_deleted(self) -> bool: ...
    @classmethod
    def builder(cls) -> B: ...             # B is the third argument you pass
    def copy(self) -> B: ...
    def next_version(self) -> Self: ...
```

Two differences from [`Model`](/reference/model/), and both are the point of the type existing:

**No `events`, and `copy()` returns an `EntityBuilder`** — which has no `with_event`. Not a
convention: there is no method to call. Writing an entity emits nothing.

**No `created_date` / `updated_date`.** An entity is state, not history. Something that needs to
know when it last changed almost certainly has changes worth telling the rest of the system
about, which makes it a `Model`. If you find yourself adding a timestamp column to an entity,
that is the signal.

It still gets `version` and optimistic locking, still gets soft deletion through `state`, and is
still staged on the plan the same way. **The unit of work that wrote it is still recorded** — one
`events` row with `event_type` null — because the audit trail is of units of work rather than of
events.

## When to use Entity rather than Model

Ask whether a change is **news**. If something downstream should learn that this row changed,
it is a model. If nobody outside this service would subscribe to it, it is an entity.

Good entities: idempotency markers, lookup and reference tables, per-row settings, alerts
already described by the event that caused them.

## Differences from Model

| | model | entity |
| --- | --- | --- |
| emits events | yes | **no** |
| `created_date` / `updated_date` | yes | **no** |
| `version`, optimistic locking | yes | yes |
| `state`, soft deletion | yes | yes |
| staged on the plan | yes | yes |
| appears in the outbox | one row per event | only inside the action's sentinel row |

An entity has no timestamps because it is state, not history — the repository refuses a table
that carries the wrong shape for the kind you declared, at construction rather than at the first
write.

Writing one is still **audited**: the action that wrote it records an invocation row, so the
audit trail is of units of work even where there are no events.

## Construction and mutation

Subclasses are **immutable** frozen dataclasses. A change produces a new instance through
`copy()...build()`, and the builder threads the version forward, so what the repository writes
carries the successor version its optimistic-locked update needs.

Where a model's mutators attach an event as they go, an entity's simply return the new value -
there is nothing to emit, so there is nothing to attach:

```python
@dataclass(frozen=True, kw_only=True)
class Currency(Entity[CurrencyId, GenericState, CurrencyBuilder]):
    code: str
    display_name: str

    def __post_init__(self) -> None:
        if not self.code.strip():
            raise ValidationError("code cannot be blank")

    def rename(self, display_name: str) -> Currency:
        return self.copy().display_name(display_name).build()
```

`__post_init__` is where a frozen dataclass puts the checks a constructor body would hold,
because there is no constructor body to put them in.

The same builder shape as a model, minus the event and timestamp methods:

```python
@classmethod
def of(cls, transfer_id: UUID, step: StepName) -> TransferStep:
    return cls(
        id=Id[TransferStep].random(),
        state=GenericState.ACTIVE,
        version=1,
        transfer_id=transfer_id,
        step=step,
    )
```

## Equality

Two entities are equal when they have the same class and the same `id`, `state` and `version`.
The business fields take no part: two currencies with one id and version
are equal whatever display name each copy carries. The hash is the id's alone.

A model compares its two timestamps as well; an entity has none. See
[Model → Equality](/reference/model/#equality).

## Builder API

`id`, `state`, `version`, `with_initial_version()`, `increase_version()`, `copy_base(other)`
and `set(**changes)`. `with_event` and the timestamp setters are **not** on it — so attaching an
event to something that does not emit them is not expressible.

Name the builder on the class line, the same as on a
[model](/reference/model/#builder-api) and for the same reason — an untyped builder is invisible
to a checker, and there is no compile step here to make that an error:

```python
class Alert(Entity[Id["Alert"], GenericState, AlertBuilder]):
    message: str
```

`copy()` and `builder()` refuse without it. The refusal is at the call, so an entity only ever
built through a factory like `Alert.create(...)` and never copied can leave it out.
`EntityBuilder(Alert)` stays reachable by name.
